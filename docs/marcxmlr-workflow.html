Statistical profiling of bibliographic metadata with marcxmlr

Lorenzo Isella

A catalogue as a statistical population

A bibliographic catalogue can be studied statistically: which kinds of subject access are present, how many subject headings are assigned to individual records, and how often do those headings carry machine-readable authority identifiers? These are descriptive questions about records and field instances, not questions about XML parsing. They also have practical uses in catalogue assessment and in identifying records for closer examination.

This vignette develops a small case study using genuine MARCXML data. It focuses on a finding that merits investigation: the occurrence of an authority identifier in topical subject fields varies strongly with the number of subject subdivisions. We do not treat the absence of an identifier as proof of a cataloguing error. The package README introduces MARCXML, the canonical representation, editing and reconstruction; those examples are deliberately not repeated here.

Dataset and limits of inference

The analysis uses 1,000 genuine bibliographic records sampled from the GPO collection and included with the package as a fixed MARCXML file. The source is the U.S. Government Publishing Office’s (GPO) Catalog of U.S. Government Publications. The frozen source corpus and reproducibility material associated with the package evaluation are documented on Zenodo.

The sample represents only part 00, not the complete GPO catalogue. Its records predominantly describe publications from the 1970s. Statistics below refer to the sample as observed and are not estimates of the whole GPO catalogue or of changes through time. This example file is included in the package so the vignette can render without a network connection. The XML data are real; any interpretation of their metadata remains conditional on cataloguing practice and context.

library(marcxmlr)
library(dplyr)

xml_file <- system.file(
  "extdata", "gpo-cgp-part00-sample.xml",
  package = "marcxmlr", mustWork = TRUE
)
marc <- read_marcxml(xml_file)

n_records <- n_distinct(marc$record_id)
field_instances <- marc |>
  filter(field_type == "datafield") |>
  distinct(record_id, field_order, tag)

overview <- data.frame(
  Measure = c("Bibliographic records", "Canonical rows", "Data-field instances"),
  Value = c(n_records, nrow(marc), nrow(field_instances))
)

The canonical format stores one row per subfield occurrence in a MARC data field. Thus a field containing $a, $x and $0 contributes three rows but only one field instance, identified by (record_id, field_order). Likewise, a record containing three 650 fields is one record but three subject-field instances. We will make each denominator explicit.

1. Coverage: how often does a record have topical subject access?

Our first unit is the bibliographic record. We measure the presence of selected MARC fields without treating any of them as mandatory for every record. For example, 650 means a topical subject added entry; other MARC fields can also represent subject access.

tags_of_interest <- data.frame(
  tag = c("245", "650", "651", "655", "710", "856"),
  meaning = c(
    "Title statement", "Topical subject", "Geographic subject",
    "Genre/form term", "Corporate added entry", "Electronic location/access"
  )
)

coverage <- field_instances |>
  filter(tag %in% tags_of_interest$tag) |>
  distinct(record_id, tag) |>
  count(tag, name = "records") |>
  right_join(tags_of_interest, by = "tag") |>
  mutate(
    records = coalesce(records, 0L),
    percent = 100 * records / n_records
  ) |>
  select(tag, meaning, records, percent)

knitr::kable(
  coverage, digits = 1,
  caption = "Record-level field coverage (denominator: all 1,000 records)."
)

2. Indexing intensity: how many topical subject fields per record?

Next we count field instances within each record. Critically, the calculation begins with all records, including those with no 650: a summary calculated only from 650 rows would omit zero-subject records and inflate the average.

subject_counts <- field_instances |>
  filter(tag == "650") |>
  count(record_id, name = "n_650") |>
  right_join(
    data.frame(record_id = unique(marc$record_id)),
    by = "record_id"
  ) |>
  mutate(n_650 = coalesce(n_650, 0L)) |>
  arrange(record_id)

subject_summary <- data.frame(
  Measure = c(
    "Records with no 650", "Mean fields per record",
    "Median fields per record", "90th percentile", "Maximum"
  ),
  Value = c(
    sum(subject_counts$n_650 == 0L), mean(subject_counts$n_650),
    median(subject_counts$n_650),
    as.numeric(quantile(subject_counts$n_650, 0.90)),
    max(subject_counts$n_650)
  )
)
subject_summary$Value <- c(

The distribution is not captured by a single average: 135 records have no 650, the median is two fields per record, and the maximum is 14. Those figures are useful as descriptions of indexing intensity; they are not thresholds for correct cataloguing.

3. Authority identifiers: use field instances, not subfield rows

Our second question concerns subfield $0, which may carry an authority record control number or standard number. The appropriate denominator is the number of field instances of each MARC tag, not the total number of canonical rows, subfields or bibliographic records.

We calculate a Boolean indicator once per field. Grouping by record_id and field_order is essential: a $0 in one 650 field must not be attributed to another 650 field in the same record.

field_profiles <- marc |>
  filter(field_type == "datafield") |>
  group_by(record_id, field_order, tag, ind2) |>
  summarise(
    has_0 = any(
      subfield_code == "0" & !is.na(value) & nzchar(trimws(value)),
      na.rm = TRUE
    ),
    n_subdivisions = sum(subfield_code %in% c("v", "x", "y", "z")),
    .groups = "drop"
  )

selected_tags <- c("100", "110", "650", "651", "655", "710")
authority_by_tag <- field_profiles |>
  filter(tag %in% selected_tags) |>
  group_by(tag) |>
  summarise(
    field_instances = n(),
    with_0 = sum(has_0),
    percent_with_0 = 100 * mean(has_0),
    .groups = "drop"
  ) |>
  arrange(tag)

knitr::kable(
  authority_by_tag, digits = 1,
  caption = "Presence of nonempty $0 by MARC field tag (field-instance denominator)."
)

The sample has nonempty $0 values in 761 of 1,771 topical 650 fields (43.0%), compared with 590 of 629 710 corporate added-entry fields (93.8%) and 222 of 223 655 genre/form fields (99.6%). These are heterogeneous metadata categories with different functions and cataloguing conventions, so their percentages should not be interpreted as a ranking of cataloguing quality. Moreover, subfield $0 presence does not prove that an identifier resolves or refers to the correct entity.

4. A more revealing association: subject subdivisions and $0

A topical 650 heading can be subdivided by form ($v), topic ($x), period ($y) or place ($z). Are authority identifiers distributed similarly among simple and subdivided topical headings?

Each row in topical_fields below represents one complete 650 field; n_subdivisions counts occurrences of $v, $x, $y and $z in that field. This is not a count of words or of distinct subdivision types.

topical_fields <- field_profiles |>
  filter(tag == "650") |>
  mutate(
    subdivision_group = factor(
      case_when(
        n_subdivisions == 0L ~ "None",
        n_subdivisions == 1L ~ "One",
        TRUE ~ "Two or more"
      ),
      levels = c("None", "One", "Two or more")
    )
  )

subdivision_profile <- topical_fields |>
  group_by(subdivision_group) |>
  summarise(
    field_instances = n(),
    with_0 = sum(has_0),
    percent_with_0 = 100 * mean(has_0),
    .groups = "drop"
  )
knitr::kable(
  subdivision_profile, digits = 1,
  caption = "Topical 650 fields by number of subdivisions and presence of $0."
)

  subdivision_profile$percent_with_0,
  names.arg = subdivision_profile$subdivision_group,

The difference is pronounced: 484 of 509 650 fields without a subdivision contain $0 (95.1%); the figure falls to 254 of 761 (33.4%) for one subdivision and 23 of 501 (4.6%) for two or more. This is an association within the observed fields, not evidence that adding subdivisions causes identifiers to disappear. In particular, an authority number may identify an established heading, while a string of subdivisions may require different treatment.

Check an important confounding factor: subject vocabulary

MARC field 650 uses its second indicator to identify the subject heading system: for example, 0 denotes Library of Congress Subject Headings, while 7 denotes a source named in $2. Since the cataloguing conventions may differ by system, a pooled percentage can conceal distinct patterns. The Library of Congress 650 documentation describes these indicators and subfields.

vocabulary_profile <- topical_fields |>
  group_by(ind2) |>
  summarise(
    field_instances = n(),
    with_0 = sum(has_0),
    percent_with_0 = 100 * mean(has_0),
    .groups = "drop"
  ) |>
  arrange(desc(field_instances))

The strong gradient remains within second-indicator 0: 383/406 (94.3%) with no subdivision, 221/728 (30.4%) with one and 19/497 (3.8%) with two or more. This descriptive check rules out the simple explanation that the overall gradient arises only because different subject heading systems were pooled. It does not exclude other sources of confounding, and fields within a record are not independent observations.

5. Return from a statistical pattern to original MARC fields

A statistical anomaly is useful when it leads to a transparent, reproducible list for human inspection. For example, we can retrieve highly subdivided 650 fields without $0, together with their original record control number and title. They are candidates for examination, not automatically errors.

control_numbers <- marc |>
  filter(field_type == "controlfield", tag == "001") |>
  transmute(record_id, control_001 = value)

titles <- marc |>
  filter(tag == "245", subfield_code == "a") |>
  group_by(record_id) |>
  summarise(title = first(value), .groups = "drop")

# Retain each subdivision's original value for human interpretation.
subject_text <- marc |>
  filter(tag == "650", subfield_code %in% c("a", "v", "x", "y", "z")) |>
  arrange(record_id, field_order, subfield_order) |>
  group_by(record_id, field_order) |>
  summarise(heading = paste(value, collapse = " -- "), .groups = "drop")

inspection <- topical_fields |>
  filter(n_subdivisions >= 2L, !has_0) |>
  arrange(desc(n_subdivisions), record_id, field_order) |>
  slice_head(n = 8L) |>
  left_join(control_numbers, by = "record_id") |>
  left_join(titles, by = "record_id") |>
  left_join(subject_text, by = c("record_id", "field_order")) |>
  select(control_001, title, heading, n_subdivisions)

The original marc table remains available for inspecting indicators, additional subfields and neighbouring fields. This is a reason to retain the canonical representation until the analytical question is settled: flattening all subjects into a single record-level string would lose the association between a particular subdivided heading and its $0.

6. From a sample to a catalogue-scale study

The sample is intentionally small enough for the vignette to build during package checks. To repeat the analysis on a full MARCXML file, point read_marcxml() at that file if the resulting table fits comfortably in R. For a larger collection, marcxml_to_parquet() stores the same canonical columns on disk. The following code is not executed by this vignette; it requires local GPO files and the optional arrow package.

input_dir <- "/path/to/benchmark-inputs"
source_files <- sort(Sys.glob(file.path(
  input_dir, "cataloging-records-all-cgp-XML-*.xml"
)))

marcxml_to_parquet(
  source_files,
  output_dir = "gpo-canonical-parquet",
  batch_records = 5000L,
  workers = 4L
)

ds <- arrow::open_dataset("gpo-canonical-parquet")

# Field-instance counts, not canonical-row counts.
by_vocabulary <- ds |>
  filter(tag == "650") |>
  distinct(record_id, field_order, ind2) |>
  count(ind2, name = "field_instances") |>
  collect()

with_id <- ds |>
  filter(tag == "650", subfield_code == "0",
         !is.na(value), value != "") |>
  distinct(record_id, field_order, ind2) |>
  count(ind2, name = "with_0") |>
  collect()

left_join(by_vocabulary, with_id, by = "ind2")

A study of the full corpus would need to document which source files were included, any malformed records excluded, the date of the extract, and the sampling frame. It would also be worthwhile to stratify by cataloguing agency, type of material, date of record modification, or other defensible covariates before interpreting differences in authority linking. A publication’s date in 008 should not be mistaken for the date when its metadata were created or enhanced.

Conclusions

This example illustrates three levels of statistical description enabled by the same canonical MARCXML representation: record-level coverage, the per-record distribution of repeated fields, and conditional frequencies at the field-instance level. The final association between $0 and subject subdivisions would be easy to mismeasure if subject field boundaries were lost. It remains a descriptive observation requiring bibliographic interpretation, not a cataloguing compliance score or a claim of causality.
